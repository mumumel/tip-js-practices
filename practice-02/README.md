## 4. Модель данных и функции

### Поля задачи
| Поле	| Правило |
| id    | Число, положительное безопасное целое: Number.isSafeInteger(id) && id > 0. В пределах списка уникально. |
| title	|Строка. После trim() длина от 1 до 100 включительно. В объект записывается очищенная строка; внутренние пробелы сохраняются. |
| completed	| Логическое значение. При создании новой задачи всегда false. |
| priority | Строго одно из значений: "low", "medium", "high". По умолчанию — "medium"., правила валидации и назначение файлов. |

**Правила валидации:** сначала проверяются типы, затем ограничения. Строковый идентификатор не преобразуется в число, null не заменяется значением по умолчанию. Ожидаемые ошибки возвращаются как объект { ok: false, error: "..." }, а не обрывают программу.

### Назначение файлов:

|Файл |	Назначение | Чего в нём нет |
|data.js	| Экспорт исходных массивов demoTasks и variantTasks, номера варианта.	| Функций изменения данных, запуска сценариев, вывода. |
|task-service.js	| Проверки полей и операции над переданными данными. |	console.log, DOM, чтения demoTasks из другого файла, глобального изменяемого списка. |
|main.js |	Импорт модулей, последовательность действий, вывод и обработка отказов. |	Дублирования реализации поиска, фильтрации и расчёта сводки. |
|checks.js	| Сравнение фактических результатов функций с ожиданиями. |	Подмены проверок заранее выведенными сообщениями OK. |

### Операции и результаты:

| Функция	| При успехе |	При ошибке |
| createTask(id, title, priority) |	{ ok: true, task: {...} }	| { ok: false, error } |
| findTaskById(tasks, id)	| найденный объект	| undefined |
| getPendingTasks(tasks) |	новый массив невыполненных | — (всегда массив) |
| getTaskTitles(tasks) |	новый массив строк	| — (всегда массив) |
| getTaskStats(tasks) | { total, completed, pending, progress }	| — (всегда объект) |
| addTask(tasks, id, title, priority) | { ok: true, tasks: [...] } |	{ ok: false, error } |
| setTaskCompleted(tasks, id, completed) | { ok: true, tasks: [...] } |	{ ok: false, error } |
| renameTask(tasks, id, title) | { ok: true, tasks: [...] } | { ok: false, error }|
| removeTask(tasks, id) | { ok: true, tasks: [...] } | { ok: false, error } |

**Почему id не равен индексу:** индекс показывает текущее место в массиве и меняется при удалении соседних элементов; id идентифицирует запись и в модели этой работы не меняется. Поиск задачи по id нельзя заменять обращением tasks[id]. 
**Почему getTaskStats возвращает число, а не строку с процентом:** расчётная функция возвращает данные для дальнейшего использования; форматирование (toFixed(1)) выполняется при отображении в main.js. Строка с процентом непригодна для дальнейших вычислений и сравнений.
**Какие объекты копируются при изменении задачи:** cоздаётся новый массив ([...tasks], map, filter) и новый объект только изменяемой записи ({ ...task, completed } или { ...task, title }). Неизменённые объекты используются повторно без изменения их свойств. Входной массив и его объекты не мутируют ни при успехе, ни при ошибке.

## 9. Вывод

По сравнению с ПР1, где проверялись условия, циклы и базовые типы, в ПР2 логика приложения выделена в отдельный ES-модуль task-service.js с девятью экспортируемыми функциями; данные (data.js), прикладная логика (task-service.js) и демонстрация (main.js) разделены через import/export. Возвращаемые значения используются для передачи данных между функциями: createTask возвращает объект результата с задачей, операции изменения — новый массив задач, функции чтения — объект, массив или сводку; форматирование прогресса (toFixed(1)) выполняет только main.js. Неизменность данных проверена двумя способами: сравнением входа с эталонной копией после каждой операции и замораживанием (Object.freeze) массива и объектов в проверке 33, где все операции успешно отрабатывают без мутации. Пришлось исправить пропущенный return в стрелочной функции с телом в фигурных скобках (эксперимент 2) — без него square(4) возвращал undefined вместо 16; также в ходе работы выявлена и устранена типичная ошибка с порядком spread-свойств в эксперименте 5.
